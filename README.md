# Adrobot — обёртка над Keitaro

Веб-приложение поверх Admin API трекера Keitaro. Две части:

1. **Создатель кампаний.** Принимает название, страну (Geo) и оффер (поиск с автодополнением). Создаёт в Keitaro кампанию с двумя потоками: первый ловит выбранную страну и редиректит на `google.com`, второй отправляет всех остальных на оффер. Домен, группа и источник берутся из настроек. Созданные кампании записываются в журнал.
2. **Редактор кампании.** Показывает потоки кампании и их офферы, позволяет добавлять офферы, убирать (Remove) и возвращать (Bring back), закреплять вес (Pin); веса пересчитываются до 100%. Изменения копятся в черновике и уходят в Keitaro только по кнопке Push to KT; Cancel откатывает черновик; Fetch Streams подтягивает состояние из Keitaro.

Бэкенд — FastAPI, SQLAlchemy 2, Alembic, httpx. Фронтенд — Angular 22 (standalone, signals). БД по умолчанию — SQLite.

## Как устроено

- **Слои:** роутеры (`api`) → сервисы (бизнес-логика: веса, синхронизация, публикация) → клиент Keitaro (единственное место, знающее формат Keitaro) → репозитории (БД).
- **Клиент Keitaro скрыт за интерфейсом:** в тестах его заменяет мок, а демо-стенд (ниже) подставляет «Keitaro» в памяти.
- **Keitaro — источник истины.** Мы храним локальное представление потоков и привязок офферов (вес, закрепление, состояние). У привязки есть рабочая и опубликованная версии; поток с различиями — черновик (жёлтый), без них — чистый (белый).
- **Push меняет только офферы потока.** Фильтры, действие, позиция и прочие настройки потока не трогаются (проверено на живом запросе, см. «Как проверялось»).
- **Расчёт весов** — чистая функция без БД и сети. Закреплённые веса не меняются, остаток делится поровну между незакреплёнными, сумма активных всегда 100%.
- Ошибки Keitaro превращаются в понятные ответы API (`{code, message}`), а не в 500. Ключ API не попадает в логи и ответы.

## Требования

- Docker с Compose, **или**
- Python ≥ 3.12, Node.js 24 (`frontend/.nvmrc` — 24.16.0) и pnpm 11 (`corepack enable` подтянет нужную версию).

## Настройка `.env`

Один файл `.env` в корне репозитория; в git он не попадает. Начните с шаблона:

```bash
cp .env.example .env
```

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `KEITARO_BASE_URL` | адрес трекера (обязательна) | — |
| `KEITARO_API_KEY` | ключ Admin API (обязательна) | — |
| `KEITARO_TIMEOUT_SECONDS` | таймаут запроса к Keitaro | `10` |
| `KEITARO_MAX_RETRIES` | повторы запросов: чтение — при ошибках сети, таймаутах и 502/503/504; запись — только если соединение не установилось | `2` |
| `KEITARO_WRITE_NAME_PREFIX` | писать (создавать, Push) можно только в кампании с таким префиксом имени; пусто — без ограничения. Рекомендуется `test_<ник>_` | пусто |
| `DATABASE_URL` | строка подключения SQLAlchemy | SQLite `backend/adrobot.db` |
| `CAMPAIGN_DOMAIN` | домен кампании, по имени или id | пусто |
| `CAMPAIGN_GROUP` | группа кампании, по имени или id | пусто |
| `CAMPAIGN_TRAFFIC_SOURCE` | источник трафика, по имени или id | пусто |
| `REDIRECT_URL` | куда ведёт поток страны | `https://google.com` |
| `OFFERS_CACHE_TTL_SECONDS` | время жизни кэша офферов для автодополнения | `300` |
| `CORS_ORIGINS` | разрешённые источники браузера (нужно только для `pnpm start`) | `["http://localhost:4200"]` |
| `KEITARO_ADMIN_LOGIN`, `KEITARO_ADMIN_PASSWORD` | доступ в админку для ручных проверок в браузере, приложением не используются | пусто |

Адрес и ключ выдаёт админка Keitaro. Для учебного эмулятора адрес выдаёт проверяющий; вход в его админку через GitHub, ключ показывает кнопка «API ключ», логин и пароль не нужны. Справочники там заданы так: `CAMPAIGN_DOMAIN=1813` (по id, имя домена отличается от настоящего), `CAMPAIGN_GROUP=FORTESTS`, `CAMPAIGN_TRAFFIC_SOURCE=FORTESTS`.

## Быстрый старт в Docker

```bash
cp .env.example .env     # заполнить KEITARO_BASE_URL, KEITARO_API_KEY, CAMPAIGN_*
docker compose up --build
```

Откройте http://localhost:8080. Устройство:

- `backend` — FastAPI; миграции (`alembic upgrade head`) применяются при каждом старте. Порт наружу не публикуется.
- `frontend` — nginx: отдаёт Angular и проксирует `/api/` на бэкенд, поэтому CORS не нужен.
- SQLite лежит в именованном томе `adrobot-data` (`DATABASE_URL` задаёт compose). Реальное имя тома начинается с имени проекта compose, обычно с имени папки, например `etlgk-adrobot_adrobot-data`; найти его можно командой `docker volume ls`.
- Swagger на порту 8080 недоступен (nginx проксирует только `/api/`); он есть при локальном запуске: http://localhost:8000/docs.

```bash
docker compose logs backend     # логи бэкенда
docker compose down             # остановить, данные сохраняются
docker compose down -v          # остановить и удалить данные (журнал, локальные потоки)
```

## Локальный запуск

### Бэкенд

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows (PowerShell / cmd)
source .venv/bin/activate       # Linux / macOS
pip install -e ".[dev]"
alembic upgrade head
uvicorn app.main:create_app --factory --reload
```

API — http://localhost:8000, Swagger — `/docs`, проверка — `GET /api/health`.

### Фронтенд

```bash
cd frontend
pnpm install
pnpm start
```

Dev-сервер — http://localhost:4200, запросы `/api` проксируются на `localhost:8000` (`frontend/proxy.conf.json`).

## Миграции

Только через Alembic; команды из `backend/`:

```bash
alembic upgrade head                              # накатить все
alembic downgrade -1                              # откатить последнюю (или: downgrade base)
alembic revision --autogenerate -m "описание"     # новая ревизия по изменению моделей
```

Любое изменение схемы БД — новая ревизия.

## Тесты и линтеры

Команды по одной в строке, чтобы они работали в любой оболочке (в Windows PowerShell 5.1 нет `&&`). Виртуальное окружение бэкенда должно быть активно.

```bash
cd backend
pytest
ruff check .
cd ../frontend
pnpm test --watch=false
pnpm lint
pnpm build
```

Без `--watch=false` `ng test` в терминале остаётся в режиме наблюдения и не завершается.

Тесты Keitaro не обращаются к сети (HTTP замокан). На начало этапа 5: бэкенд — 353 теста, фронтенд — 80.

## Демо-стенд

Бэкенд приложения над «Keitaro» в памяти: `.env` не читается, реальный трекер не нужен, БД — одноразовый SQLite-файл. Заполнен как сцена из видео.

```bash
cd backend
python -m tools.demo_stand [--port 8000]
```

Затем `pnpm start` во `frontend/` — интерфейс работает против стенда. Маршруты `/demo` показывают, что сейчас лежит в «Keitaro» (например `GET /demo/keitaro/streams/2`), и позволяют удалить оффер там, как это сделал бы пользователь в админке Keitaro. Чего стенд не проверяет — см. `docs/decisions.md`, «Что стенд не проверяет».

## Вспомогательные команды

Запускаются из `backend/` и читают `.env`; подробности — в docstring каждого модуля.

| Команда | Что делает |
|---|---|
| `python -m app.cli.recon` | только чтение: домены, группы, источники, офферы Keitaro и как разрешаются `CAMPAIGN_*` |
| `python -m tools.compare_campaigns ЭТАЛОН КАНДИДАТ [--record ИМЯ]` | только чтение: сравнение двух кампаний и их потоков поле за полем |
| `python -m tools.stream_snapshot save ID ФАЙЛ` и `diff ID ФАЙЛ` | только чтение: снимок потока до Push и сравнение после |
| `python -m tools.archive_test_campaign ID --confirm` | убирает тестовую кампанию; работает только при заданном `KEITARO_WRITE_NAME_PREFIX` и совпадении префикса |
| `python -m tools.keitaro_probe --confirm-writes` | разведка этапа 1, **пишет в Keitaro**; оставлена как история, записанные примеры уже лежат в `docs/keitaro-examples/` |

Внимание: на учебном эмуляторе `DELETE` удаляет объект безвозвратно (архива нет), поэтому `archive_test_campaign` и компенсация создателя там стирают данные навсегда. На настоящем Keitaro объекты уходят в архив.

## Принятые решения

Подробно — в [`docs/decisions.md`](docs/decisions.md); здесь по одной строке (в скобках — раздел журнала).

- **Округление весов** — целые проценты, остаток от деления раздаётся по +1 первым офферам, сумма ровно 100 («Округление весов»).
- **Крайние случаи закрепления** — закрепить сверх 100% нельзя; если все закреплены и сумма не 100, поток помечается проблемой и Push запрещён («Крайние случаи закрепления»).
- **Fetch при черновике** — неопубликованные изменения не затираются, пользователь предупреждается; `force=true` отбрасывает их («Fetch Streams», «Fetch и черновики»).
- **Cancel** — откатывает весь черновик потока, включая удаления и возвраты («Cancel»).
- **Добавление в поток без офферов** — только в потоки, где офферы уже есть («Добавление оффера»).
- **Выбор кампании** — список кампаний Keitaro с поиском по имени и id («Выбор кампании в редакторе»).
- **Защита записи префиксом** — `KEITARO_WRITE_NAME_PREFIX` ограничивает создание и Push («Защита от записи в чужие кампании»).
- **Компенсация** — при сбое создания созданное убирается (потоки, затем кампания), ошибка пишется в журнал («Компенсация при сбое создания»).
- **История не переписывается** — коммиты остаются как есть, force-push не используется («История не переписывается (владелец)»).

## Как проверялось

- **Тесты** — расчёт весов, переходы состояний, синхронизация, публикация, клиент Keitaro на моке HTTP, компоненты и мапперы фронтенда.
- **Эталон из админки** — кампания, созданная приложением, сравнена поле за полем с собранной руками: расхождений нет ([пример 25](docs/keitaro-examples/25-creator-vs-reference.json)).
- **Живая проверка редактора** — сценарий из видео на учебном эмуляторе Admin API, а не на настоящем Keitaro; поток сравнён со снимком до первого Push, изменились только офферы ([пример 26](docs/keitaro-examples/26-editor-push-check.json)).
- **Демо-стенд** — сценарий из видео в браузере.
- **Прогон через Docker** — тот же сценарий на стеке `docker compose`; результат — в `docs/decisions.md`, раздел этапа 5.

Реальные запросы и ответы Keitaro — в `docs/keitaro-examples/` ([описание](docs/keitaro-examples/README.md)).

## Ограничения

- Эмулятор воспроизводит Admin API, но не равен Keitaro: формат ответов и крайние случаи могут отличаться.
- Трафик через созданные кампании не проверялся — только состояние в Admin API.
- Фильтры и адрес редиректа потоков редактор не разбирает и не меняет.
- Драйвер Postgres в зависимости не входит: другую БД можно подставить строкой `DATABASE_URL`, поставив драйвер самостоятельно.
