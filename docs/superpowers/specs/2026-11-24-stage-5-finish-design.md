# Этап 5 — финиш: дизайн

Короткий дизайн: этап небольшой, код приложения не меняется.

## Зачем

Сдать проект проверяющему. Он клонирует репозиторий, заполняет `.env`, поднимает всё одной командой и проходит сценарий из видео; README объясняет, как проект устроен и какие решения приняты.

## Цели

1. `README.md` в корне (раздел 12 `CLAUDE.md`).
2. Docker: compose из двух контейнеров.
3. `.env.example` с подсказками для эмулятора и Docker.
4. История коммитов: без переписывания, проверка всей истории на секреты.
5. Ручной прогон всего сценария из видео на эмуляторе Keitaro через Docker-стек, результат — в `docs/decisions.md`.
6. Уборка: `.gitignore`, старый worktree этапа 3.

## Не цели

- Переписывать историю (владелец: не переписывать).
- Менять код приложения. Исключение — ошибка, найденная прогоном: тогда исправление с тестом отдельным коммитом.
- Postgres в compose: драйвера нет в зависимостях, основная база по требованиям — SQLite; подключение Postgres через `DATABASE_URL` описывается в README.
- Профиль `demo` в compose (владелец выбрал два контейнера). Демо-стенд остаётся локальной командой и описан в README.
- CI.

## Анти-цели

- Секрет в репозитории или в образе: `.env` не копируется в образы, он только передаётся контейнеру при запуске.
- Docker, который собирается, но не работает: проверяется ручным прогоном через этот стек.
- README с командами, которые не работают: каждая команда выполнена при написании.

## Подходы (Docker)

- **A. Два контейнера в compose — выбран владельцем.** `backend` (Python, миграции при старте, uvicorn) и `frontend` (сборка Angular, nginx отдаёт статику и проксирует `/api` в `backend`). Совпадает с общим дизайном («compose: бэкенд + собранный фронтенд»), код приложения не меняется, фронтенд и API на одном адресе — CORS не нужен.
- **B. Один контейнер, FastAPI отдаёт фронтенд.** Отклонён: меняет код бэкенда (статика, переход на `index.html`), смешивает слои, расходится с дизайном.

## Как

### Docker

- `backend/Dockerfile`: `python:3.14-slim` (на 3.14 проходят тесты), установка пакета из `pyproject.toml`, непривилегированный пользователь. При старте контейнера — `alembic upgrade head`, затем `uvicorn app.main:create_app --factory --host 0.0.0.0 --port 8000`. Тесты и демо-стенд в образ не попадают.
- `frontend/Dockerfile`: шаг сборки на `node:24-alpine` (как `.nvmrc`), pnpm через corepack, `pnpm install --frozen-lockfile`, `pnpm build`; шаг запуска — `nginx:alpine` со сборкой и `nginx.conf`: переход на `index.html` для маршрутов Angular, `/api/` проксируется в `backend:8000`.
- `docker-compose.yml` в корне: `backend` — `env_file: .env`, `DATABASE_URL=sqlite:////data/adrobot.db`, именованный том для `/data`, healthcheck по `/api/health`; `frontend` — порт `8080:80`, стартует после того, как `backend` здоров.
- `.dockerignore` для обоих контекстов: `.venv`, `node_modules`, `dist`, базы, кэши, `.env`.
- Запуск: `cp .env.example .env`, заполнить, `docker compose up --build`, открыть `http://localhost:8080`.

### Ручной прогон

Через `docker compose up --build` против эмулятора, браузер — Playwright MCP. Кампания `test_oso4lq_final_run`, созданная страницей Create. Шаги — как приёмка этапа 4: Create → Fetch → Add → Push → Add → Cancel → Remove → Push → Bring back → Push → удаление офферов в админке эмулятора → Fetch → Pin → Bring back → Push; плюс Fetch при черновике. После каждого шага экран сверяется с Keitaro; неизменность остальных настроек потока — `tools.stream_snapshot` (снимок до первого Push вне репозитория). Кампания остаётся в эмуляторе (архива нет). Отдельно на чистой базе: `alembic downgrade base` и снова `upgrade head`.
